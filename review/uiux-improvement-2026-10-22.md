# UI/UX 补充分析：让教师顺畅完成课堂转写

日期：2026-10-22。范围：现有 HTML/CSS/JavaScript、项目设计约束及已审查的后端行为；只做分析，没有修改界面。

## 核心判断

**值得改进。已有结构可以保留，优先减少误解、误操作和长时间等待时的不确定感。**

项目的 `.impeccable.md` 已明确主要用户是非技术教师，核心任务是“上传 → 等待 → 下载”，风格是温和、安心、简洁。现有浅深主题、离线 SVG、明显的新建入口、渐进转写、暂停自动滚动和复制全文按钮都应保留。

本轮是静态流程审查，没有浏览器截图、读屏实测或用户访谈。因此不虚构美观分数、对比度、点击热区尺寸或真实用户成功率；以下将源码可确认的问题与需要视觉验证的建议分开。

## 首轮最优先处理的五项

| 优先级 | 当前问题 | 对教师的影响 | 最小改进 |
|---|---|---|---|
| P1 | 上传只有“提交中…”，“取消”只收起表单 | 不知道大文件是否传完，以为取消后任务仍继续 | 分开上传与转写状态；显示真实上传进度，取消真正停止请求 |
| P1 | 筛选后保留隐藏的选择，删除确认只报数量 | 可能删除当前列表看不到的项目 | 筛选时清空选择，或明确显示隐藏选择并列出待删名称 |
| P1 | 质量选项只叫 fast/balanced/high | 容易选中不适合精细字幕的模式，期待不存在的质量差异 | 按用途说明“字幕转写（推荐）”“快速文字（无精细时间戳）” |
| P2 | 完成后页面仍只保留最近 80 段 | 无法直接回看整堂课开头，被要求下载 JSON 看完整内容 | 完成态提供全文阅读、搜索和分段加载，保留 DOM 数量优化 |
| P1 | AI 阅读层缺少焦点进入、约束和返回 | 键盘操作可能进入背景，关闭后难以回到原按钮 | 补齐模态层焦点管理，保留已有 Escape 与关闭按钮 |

“小”成本表示局部交互或文案调整；“中”成本表示跨状态、任务或阅读组件协调。下面是具体依据与设计方向。

## 1. 上传状态与取消必须兑现用户理解

位置：[取消事件](/E:/classroom-asr-ascii/asr/web/static/list.js:194)、[提交过程](/E:/classroom-asr-ascii/asr/web/static/list.js:344)。

大录像上传期间，按钮仅显示“提交中…”，随后直接等待 `fetch` 完成。取消只隐藏和清空表单，没有终止在途请求；用户取消后仍可能在响应返回时被带到任务页。

建议明确分为“选择录音 → 正在上传 → 等待或正在转写”。上传时展示已发送大小与真实百分比；如果暂时做不到可测进度，至少明确“正在上传，请稍候”，不能把模拟百分比当真实进度。“取消上传”应中止请求；如果服务端已经接收并创建任务，还需按任务生命周期处理，不能只取消前端等待。

成本：中。实现命令方向：`/harden`，验收要覆盖慢速大文件、取消和服务器已接收的边界。

## 2. 批量操作保持明确的作用范围

位置：[选择集合](/E:/classroom-asr-ascii/asr/web/static/list.js:13)、[筛选事件](/E:/classroom-asr-ascii/asr/web/static/list.js:373)、[删除确认](/E:/classroom-asr-ascii/asr/web/static/list.js:442)。

当前跨搜索与筛选保留 `selectedIds`，但删除确认只说明数量。最简单的方案是搜索或筛选改变时取消选择；如确实需要跨筛选选择，则提示“已选 5 项，其中 2 项不在当前结果中”，并在删除前列出名称与删除范围。

列表还有一个明确的文案错误：[空结果判断](/E:/classroom-asr-ascii/asr/web/static/list.js:41) 对所有空结果都显示“还没有转写项目”。应区分首次空列表和筛选零结果；后者显示“没有符合条件的项目”，提供“清除搜索与筛选”。

成本：小。实现命令方向：`/harden`、`/clarify`。不必为了这个问题建设复杂的撤销或回收站系统。

## 3. 选择项告诉用户会得到什么

位置：[质量与 AI 选项](/E:/classroom-asr-ascii/asr/web/static/index.html:59)、[模型选择说明](/E:/classroom-asr-ascii/asr/engines/funasr_engine.py:71)。

`fast（最快） / balanced（默认） / high` 是实现术语。教师关心的是能否做字幕、是否有时间戳、要等多久。当前 fast 不提供精细时间戳；balanced 与 high 当前使用同一 ASR 模型，没有经过本轮质量对比，界面不应暗示 high 必然更准确。

建议普通入口保留“字幕转写（推荐）”与“快速文字（无精细时间戳）”；英文模式名放说明或高级设置。若暂时保留 high，应准确解释当前差异，不承诺未验证的收益。后端既有枚举和历史任务参数保持兼容。

说话人分离可改为“区分教师与学生发言（实验性）”，并说明结果可能需要核对；AI 项则解释它会生成点评与整理稿，而不是要求教师先理解 LLM。

成本：小。实现命令方向：`/clarify`、`/distill`。

## 4. 完成后的转写应该能在页面内完整阅读

位置：[80 段上限](/E:/classroom-asr-ascii/asr/web/static/task.js:10)、[折叠处理](/E:/classroom-asr-ascii/asr/web/static/task.js:355)、[完整内容提示](/E:/classroom-asr-ascii/asr/web/static/task.js:373)。

当前 DOM 只保留最近 80 段，旧段从页面移除，提示“查看完整请下载 JSON”。对长课堂而言，下载开发者数据格式不是教师回看第一段的合适路径。当前复制全文使用完整数组，这个能力已经有，不需要重复新增。

建议区分“实时跟随”和“完成后阅读全文”：运行中保持轻量滚动；完成后提供搜索、按时间定位、分页或虚拟列表，让完整稿件都可访问，避免一次渲染全部段落。若后续明确有校对需求，再增加音频回听；它涉及媒体播放与数据访问，不是本轮最小改动。

成本：中。实现命令方向：`/arrange`、`/optimize`。

## 5. 阅读层把键盘流程补完整

位置：[dialog 语义](/E:/classroom-asr-ascii/asr/web/static/task.html:144)、[打开与关闭](/E:/classroom-asr-ascii/asr/web/static/task.js:636)、[Escape 关闭](/E:/classroom-asr-ascii/asr/web/static/task.js:664)。

现有 `role="dialog"`、`aria-modal`、标题关联、关闭按钮和 Escape 支持是正确基础。代码没有在打开时将焦点送入阅读层，没有限制 Tab 留在弹层，也没有关闭后把焦点还给原按钮。

建议补齐这三步，阻止模态打开时背景继续交互；长报告可把初始焦点放在标题，便于从头阅读。依据可参考 [WAI 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。后续用纯键盘实际验证，不能只加 ARIA 属性就算完成。

成本：小至中。实现命令方向：`/harden`。

## 第二轮值得推进的改进

### 等待时优先回答“正在做什么、我能做什么”

[任务阶段](/E:/classroom-asr-ascii/asr/web/static/task.html:53) 展示探测、提取、降噪、识别、后处理、写文件等工程步骤。建议主视图收为“准备录音 / 生成文字 / 整理结果”，具体阶段留在可展开详情。

首次出字前给转写区域上下文提示；识别进行中优先展示可验证的“已处理录音 X 分钟 / 总长 Y 分钟”。计时只能表示已用时间，不能伪装成后台仍正常工作的心跳；没有可靠估计就不显示精准剩余时间。

转写完成但 AI 仍运行时，明确写“转写已完成，可以下载；AI 点评生成中”，让教师知道已能完成主要任务，不必等完 AI。

### 下载按用途分组，长 AI 稿提供更好的阅读出口

[下载区域](/E:/classroom-asr-ascii/asr/web/static/task.html:72) 同时展示 SRT、TXT、VTT、MD、JSON。建议首层保留“下载字幕（SRT）”“下载文字稿（TXT）”，其余放“更多格式”，并只展示实际可用的产物。

AI 三件可统一为“教学点评 / 整理后的逐字稿 / 课堂讲义”，各自有一句用途说明。短点评可继续用弹层；长讲义给可选的全屏阅读、目录和字体调节，原文与修改痕迹保留清晰入口。下载说明应直接告诉教师拿到的文件用途。

### 设置用中文，保存后回到原任务

[设置表单](/E:/classroom-asr-ascii/asr/web/static/settings.html:43) 可以先展示“服务商 / 模型 / 密钥”，将地址、超时与输出上限放进高级设置。字段使用“服务地址”“访问密钥”“模型名称”，技术名称作为辅助说明。

[跳转设置](/E:/classroom-asr-ascii/asr/web/static/task.js:264) 和 [保存结果](/E:/classroom-asr-ascii/asr/web/static/settings.js:101) 没有把教师接回原任务。建议携带来源，保存后提供“返回《项目名》并生成反馈”；需要调用 LLM 时仍应由用户明确触发，不能保存后自动产生额外调用。

在选择云端服务并开启 AI 反馈的位置，说明“转写在本机进行；AI 将把逐字稿发送至所配置的服务”。这是当前数据流中有意义的选择信息，不应只藏在开发文档中。

### 窄屏与长文排版保护核心信息

[窄屏规则](/E:/classroom-asr-ascii/asr/web/static/style.css:518) 在 700px 以下隐藏表格第 2 列，而当前第 2 列正是项目名。应保留项目名，将文件名、段数、创建时间降为次要信息；实际换行和溢出仍需浏览器确认。

转写正文当前约 13.5px、AI 正文约 14.5px。面向长时间阅读，可以以 16px 左右作为验证起点，增加可选阅读宽度或字号；不要求把管理表格所有文字一起放大。保留系统字体与本地 SVG，不引入外部字体、装饰渐变或与任务无关的动效。

## 三类用户的具体障碍

- 首次使用的教师：不知道 fast 会失去什么，看到 max_tokens 不知道是否必须调整，配置完还需要重新找任务。
- 经常处理多堂课的教师：跨筛选隐藏选择使删除范围不透明；零搜索结果被说成“还没有项目”。
- 键盘使用者与长文阅读者：弹层焦点行为不完整；完成态回看全文缺少直接入口。

## 建议推进顺序

第一轮先兑现上传取消、明确删除范围、解释质量选项、补齐弹层键盘行为。随后做好完成态全文阅读、状态文案和下载分组。视觉微调最后围绕正文阅读、主次层级和窄屏主信息推进。

后续可按 `/harden → /clarify → /distill → /arrange → /adapt → /polish` 分批实现；这些是技能方向，不表示本轮已修改。每批实现都需具体计划与浏览器验收。
